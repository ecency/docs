The `@ecency/sdk/wallets` entry point is the wallet layer of the Ecency web app. It ships inside the
[Ecency SDK](/developers/sdk/) (from version 2.6.0) and gives you:

- Asset queries for Hive (HIVE, HP, HBD), Hive Engine tokens and Ecency Points, re-exported from the SDK.
- Token price and token list queries.
- External chain balances (BTC, ETH, BNB, SOL) and MetaMask transfers for ETH, BNB and SOL.
- MetaMask multichain discovery and Hive Snap helpers.
- Hive key derivation from a BIP44 seed or a master password.
- Helpers to save linked wallet addresses to the Hive profile.

It is part of the [`@ecency/sdk`](https://www.npmjs.com/package/@ecency/sdk) package (MIT license). The source is in
[ecency/vision-web](https://github.com/ecency/vision-web/tree/develop/packages/sdk/src/wallets) under
`packages/sdk/src/wallets`.

## Installation

There is no separate package to install. Install the SDK with HiveSigner, React Query and React:

```sh
npm install @ecency/sdk hivesigner @tanstack/react-query react
```

The wallets entry imports React Query when it loads, so the import fails without `@tanstack/react-query` and
`react`, even if you only use the plain functions. The SDK lists both as optional peers, so npm doesn't add them
for you.

Then import wallet code from the `@ecency/sdk/wallets` subpath:

```ts
import { getTokenPriceQueryOptions, EcencyWalletCurrency } from "@ecency/sdk/wallets";
```

Peer dependencies of `@ecency/sdk`:

| Package | Version | Required |
|---|---|---|
| `hivesigner` | `^4.0.0` | Yes |
| `@tanstack/react-query` | `>=5` | Yes for `@ecency/sdk/wallets` (imported when the entry loads) |
| `react` | `>=18` | Yes for `@ecency/sdk/wallets` (needed by React Query) |
| `@solana/web3.js` | `^1` | Optional, only for SOL transfers |
| `@wallet-standard/app` | `^1` | Optional, only for MetaMask multichain discovery and SOL transfers |

The Solana and Wallet Standard packages are loaded only when you call a function that needs them. You can leave
them out if you use neither SOL transfers nor MetaMask multichain discovery. At runtime, without
`@wallet-standard/app`, discovery returns only the EVM address (no SOL or BTC).

Configure the SDK first (at least `ConfigManager.setQueryClient`), as described on the [SDK page](/developers/sdk/).

## Supported currencies

| Currency | Balance query | Transfer via MetaMask | How it signs |
|---|:---:|:---:|---|
| BTC | Yes | No | |
| ETH | Yes | Yes | `eth_sendTransaction` |
| BNB | Yes | Yes | `eth_sendTransaction` with chain switch |
| SOL | Yes | Yes | Wallet Standard `solana:signAndSendTransaction` |

The `EcencyWalletCurrency` enum has the values `BTC`, `ETH`, `BNB` and `SOL`. `EcencyWalletBasicTokens` has
`POINTS`, `HP`, `HIVE` and `HBD`.

## Asset queries

These query option builders live in the main SDK and are re-exported by `@ecency/sdk/wallets`, so you can import
them from either `@ecency/sdk` or `@ecency/sdk/wallets`.

### Hive

| Function | Returns |
|---|---|
| `getHiveAssetGeneralInfoQueryOptions(username)` | HIVE balance, savings and price info |
| `getHbdAssetGeneralInfoQueryOptions(username)` | HBD balance, savings and interest info |
| `getHivePowerAssetGeneralInfoQueryOptions(username)` | Hive Power, delegations and power down info |
| `getHiveAssetTransactionsQueryOptions(username, limit?, filters?)` | HIVE history (infinite) |
| `getHbdAssetTransactionsQueryOptions(...)` / `getHivePowerAssetTransactionsQueryOptions(...)` | HBD and HP history |
| `getHiveAssetMetricQueryOptions(...)` | HIVE market metrics |
| `getHiveAssetWithdrawalRoutesQueryOptions(username)` | Power down withdraw routes |
| `getHivePowerDelegatesInfiniteQueryOptions(...)` | Outgoing HP delegations |
| `getHivePowerDelegatingsQueryOptions(username)` | Incoming HP delegations |
| `getAccountWalletAssetInfoQueryOptions(username, asset, { currency? })` | One asset's info for any asset symbol (HIVE, HP, HBD, POINTS or an engine token) |

### Hive Engine

`getAllHiveEngineTokensQueryOptions`, `getHiveEngineTokensBalancesQueryOptions(username)`,
`getHiveEngineBalancesWithUsdQueryOptions`, `getHiveEngineTokenGeneralInfoQueryOptions(username, symbol)`,
`getHiveEngineTokensMetadataQueryOptions`, `getHiveEngineTokenTransactionsQueryOptions`,
`getHiveEngineTokensMetricsQueryOptions`, `getHiveEngineTokensMarketQueryOptions` and
`getHiveEngineUnclaimedRewardsQueryOptions`.

### Ecency Points

| Function | Returns |
|---|---|
| `getPointsQueryOptions(username, filter?)` | Points balance, unclaimed Points and transactions |
| `getPointsAssetGeneralInfoQueryOptions(username)` | Points as a wallet asset |
| `getPointsAssetTransactionsQueryOptions(...)` | Points history |

Points mutation: `useClaimPoints(username, accessToken, onSuccess?, onError?)` claims pending Points.

### Wallet operations

`useWalletOperation(username, asset, operation, auth?)` runs a wallet action for an asset. `operation` is an
`AssetOperation` value such as `Transfer`, `TransferToSavings`, `WithdrawFromSavings`, `Delegate`, `PowerUp`,
`PowerDown`, `ClaimInterest`, `Convert`, `Gift`, `Claim`, `Stake`, `Unstake` or `Undelegate`.

```tsx
import { useQuery } from "@tanstack/react-query";
import { getAccountWalletAssetInfoQueryOptions, useWalletOperation, AssetOperation } from "@ecency/sdk/wallets";

const { data: hive } = useQuery(getAccountWalletAssetInfoQueryOptions("alice", "HIVE"));

const transfer = useWalletOperation("alice", "HIVE", AssetOperation.Transfer, auth);
```

## Wallet queries

| Function | Returns |
|---|---|
| `getTokenPriceQueryOptions(currency)` | Latest USD price for a currency (BTC, ETH, SOL, BNB, HBD, HIVE) |
| `getAllTokensListQueryOptions(username?)` | `{ basic, external, layer2 }`: the basic tokens, external currencies and Hive Engine tokens |
| `getAccountWalletListQueryOptions(username, currency?)` | The token symbols the user chose to show in their wallet |
| `getTokenOperationsQueryOptions(token, username, isForOwner?, currency?)` | The `AssetOperation` values available for a token |
| `useGetExternalWalletBalanceQuery(currency, address)` | Balance of an external address (`balanceString`, `balanceBigInt`, `unit`) |

```ts
import { useQuery } from "@tanstack/react-query";
import { getTokenPriceQueryOptions, useGetExternalWalletBalanceQuery, EcencyWalletCurrency } from "@ecency/sdk/wallets";

const { data: ethUsd } = useQuery(getTokenPriceQueryOptions("ETH"));
const { data: balance } = useGetExternalWalletBalanceQuery(EcencyWalletCurrency.ETH, "0x...");
```

## MetaMask discovery

```ts
import { discoverMetaMaskWallets, installHiveSnap, getHivePublicKeys } from "@ecency/sdk/wallets";

// Discover ETH, BNB, SOL and BTC addresses from MetaMask
const addresses = await discoverMetaMaskWallets();
// { ETH: "0x...", BNB: "0x...", SOL: "7xyz...", BTC: "bc1..." }

// Install the Hive Snap and read Hive public keys
await installHiveSnap();
const hiveKeys = await getHivePublicKeys();
// [{ publicKey: "STM...", role: "owner", accountIndex: 0, addressIndex: 0 }, ...]
```

Related helpers: `fetchMultichainAddresses()` and `fetchEvmAddress()`.

## Sending ETH, BNB or SOL

`useExternalTransfer(currency)` is a mutation that signs with MetaMask. It accepts `ETH`, `BNB` or `SOL`.

```tsx
import { useExternalTransfer, EcencyWalletCurrency } from "@ecency/sdk/wallets";

function SendEthButton({ linkedAddress }: { linkedAddress: string }) {
  const transfer = useExternalTransfer(EcencyWalletCurrency.ETH);

  const handleSend = async () => {
    const result = await transfer.mutateAsync({
      to: "0xRecipientAddress...",
      amount: "0.05",
      expectedFrom: linkedAddress,
    });
    console.log("Tx hash:", result.txHash);
  };

  return <button onClick={handleSend}>Send 0.05 ETH</button>;
}
```

Payload fields:

| Field | Description |
|---|---|
| `to` | Recipient address |
| `amount` | Amount as a decimal string |
| `expectedFrom` | EVM only, optional. The address the user linked. If the active MetaMask account is a different address, the send is blocked so funds never leave the wrong account. |

The result is `{ txHash, currency }`. On success, cached external balances are invalidated.

<Aside type="note">
  MetaMask handles gas, signing and broadcasting. The user sees the normal MetaMask confirmation. For SOL the
  Wallet Standard protocol is used instead of `window.ethereum`.
</Aside>

Lower-level helpers: `sendEvmTransfer(to, amountWei, currency, expectedFrom?)`, `ensureEvmChain`,
`estimateEvmGas`, `parseToWei`, `formatWei`, `getEvmChainConfig`, `getEvmExplorerUrl`, `sendSolTransfer(to, amountSol)`,
`parseToLamports`, `formatLamports` and `getSolExplorerUrl`.

## Hive key derivation

```ts
import { deriveHiveKeys, deriveHiveMasterPasswordKeys, detectHiveKeyDerivation } from "@ecency/sdk/wallets";

// From a BIP44 seed phrase
const keys = deriveHiveKeys(mnemonic); // { owner, active, posting, memo, ownerPubkey, ... }

// From a classic master password
const legacy = deriveHiveMasterPasswordKeys("alice", masterPassword);

// Which scheme matches the account on chain?
const kind = await detectHiveKeyDerivation("alice", seedOrPassword); // "bip44" | "master-password" | "unknown"
```

Single-role versions are `deriveHiveKey(mnemonic, role, accountIndex?)` and
`deriveHiveMasterPasswordKey(username, password, role)`. See the [seed phrase migration guide](/guides/seed-phrase-migration/)
for what this means for users.

## Saving wallet addresses to the profile

`useSaveWalletInformationToMetadata(username, auth?, options?)` writes linked wallet addresses and the wallet token
list to the user's Hive profile (`profile.tokens`). Ecency's apps read the visible wallet tokens from there.

<Aside type="caution">
  `profile.tokens` is written as a whole. If you pass a list that includes non-chain entries (for example, the
  token picker list), any token you leave out is removed from the profile. A list with only external chain
  entries keeps the other entries.
</Aside>

## Migrating from @ecency/wallets

Wallet code used to ship as the separate `@ecency/wallets` package. It now lives in the SDK, and `@ecency/wallets` is
deprecated on npm ("Moved to @ecency/sdk/wallets"). The exports are the same, so migrating is an import path change:

```sh
npm uninstall @ecency/wallets
npm install @ecency/sdk@^2.6.0 hivesigner @tanstack/react-query react
```

```diff
- import { useExternalTransfer, EcencyWalletCurrency } from "@ecency/wallets";
+ import { useExternalTransfer, EcencyWalletCurrency } from "@ecency/sdk/wallets";
```

You no longer need `--legacy-peer-deps` or `legacy-peer-deps=true` in `.npmrc` for this; a plain install works.

The last release of `@ecency/wallets` (7.0.1) is a thin shim that re-exports `@ecency/sdk/wallets` and depends on
`@ecency/sdk` `^2.6.0`, so existing code keeps working while you switch. No further releases are planned.

Upgrading to SDK 2.6.0 also brings the vote-free post shape from 2.5.0. See
[Entries and votes](/developers/sdk/#entries-and-votes) on the SDK page if your code reads `active_votes`.
